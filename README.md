# ذهب مصر | Egypt Gold Dashboard

لوحة أسعار ذهب RTL تعمل كصفحات ثابتة على GitHub Pages. **لا تتضمن أي أسعار تجريبية أو وهمية.** تُملأ البيانات بعد أول تشغيل ناجح لـ GitHub Actions.

## آلية العمل

- `scripts/fetch_gold.py`: يفتح [FoudaLens](https://foudalens.com/ar/rates/gold) عبر متصفح Chromium ويقرأ الأسعار المعروضة للأعيرة 24 و21 و18 و14، ويرفض التسجيل عند نقص سعر أو فشل تحقق تناسق الأعيرة. لا يحسب سعر عيار من آخر.
- `.github/workflows/fetch-gold.yml`: محاولة جمع كل 5 دقائق (توقيت GitHub تقريبي، قد تتأخر أو تفوت بعض الدورات). يحفظ القراءات في `data/history.json` ويعمل commit تلقائيًا.
- الموقع: يقرأ ملف JSON المنشور، ويجمعه مع بيانات `localStorage`، ويحتفظ بها بعد إغلاق المتصفح. عرض التغير مبني على آخر **قراءتين مسجلتين**. تُسجَّل كل قراءة ناجحة ولو ثبت السعر، فتظهر حالة الثبات (صفر جنيه وصفر بالمئة) بدقة.
- الزر «تحديث الآن» يعيد تحميل آخر JSON المنشور فقط؛ لا يشغّل GitHub Action لحظيًا. يمكن تشغيل عملية الجمع من تبويب Actions.
- السجل في المستودع مشترك بين كل الأجهزة؛ `localStorage` مجرد نسخة محلية مساعدة.

## نشر GitHub Pages خطوة بخطوة

1. أنشئ مستودع GitHub **عامًّا** جديدًا، مثل `egypt-gold-dashboard`، وارفع محتويات هذا المجلد إلى جذر فرع **`main`** (لا ترفع المجلد الأب فقط). أضف `.github` و`.nojekyll` مع بقية الملفات.
2. في **Settings → Actions → General → Workflow permissions** اختر **Read and write permissions** ثم Save؛ وإلا فلن يستطيع الـ Action حفظ JSON.
3. من **Actions** اختر **Fetch Gold Prices** ثم **Run workflow** على فرع `main`. راجع تفاصيل التشغيل وتحقق من ظهور أسعار حقيقية داخل `data/history.json`.
4. من **Settings → Pages → Build and deployment** اختر **Deploy from a branch**، ثم **Branch: main** و **Folder: /(root)** ثم Save.
5. افتح `https://USERNAME.github.io/egypt-gold-dashboard/` بعد انتهاء النشر. ستقرأ الواجهة `data/history.json` بمسار نسبي صالح أيضًا على صفحات المشاريع.
6. جرّب إعادة تحميل الصفحة؛ ثم تحقق من حقل «آخر جلب ناجح» ومن بيانات Actions ومن تزايد التاريخ عند تغير الأسعار.

**مهم:** تشغيل GitHub Actions بالجدولة ليس خدمة دقيقة كل خمس دقائق، وGitHub قد يعطّل scheduled workflows تلقائيًا في المستودعات العامة بعد فترة خمول طويلة. يعتمد التشغيل أيضًا على السماح بإجراء scraping من جهة الموقع. إذا تغيّر تصميم FoudaLens، قد يحتاج محدد الأسعار في `scripts/fetch_gold.py` تحديثًا. لا يتم توليد أسعار افتراضية عند الفشل.

## تشغيل محلي

```bash
python -m http.server 8000
# افتح http://localhost:8000
```

لجمع بيانات محليًا (يتطلب اتصال إنترنت على جهازك):

```bash
pip install -r requirements.txt
python -m playwright install chromium
python scripts/fetch_gold.py
python -m unittest discover -s tests
```

## تشخيص الأعطال

- `Missing verified price` أو `Could not reliably extract`: محتوى الصفحة تغيّر أو لم يُحمّل. افحص سجلات تنفيذ الـ Action وقارنها بواجهة FoudaLens، ثم عدّل أداة استخراج الكروت؛ **لا تتجاوز اختبارات التحقق بإدخال أسعار مخترعة**.
- `403` أو `429`: قد يقيّد المصدر الروبوتات. قلل وتيرة الجلب أو اطلب وصول API رسميًا بدل الالتفاف على الحظر.
- خطأ `403` عند `git push`: فعّل صلاحيات Read and write.
- الواجهة تعرض بيانات قديمة: راجع آخر تشغيل Actions وحالة النشر. وقت الجلب يختلف عن وقت آخر تغيير في السعر؛ لا يعني تأخر التغير أن البيانات مفقودة.
- GitHub Pages لا يشغّل Python ولا Chromium؛ التشغيل يتم حصريًا بواسطة Actions.
